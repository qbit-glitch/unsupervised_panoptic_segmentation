# Cluster-to-Class LUT: Why Motorcycle and Traffic Light Stay Dead

**Date:** 2026-05-05
**Branch:** `dino-cause-dora-adapter`
**Author:** MBPS team
**Audit subject:** `weights/kmeans_centroids_k80_santosh.npz` (the cluster→trainID lookup
table used by the DCFA+SIMCF+DepthPro pseudo-label pipeline).

---

## Finding

The 80-cluster lookup table maps each k-means cluster ID `c ∈ [0, 80)` to a
Cityscapes train ID `t ∈ [0, 19)`. Counting how often each train ID appears
as a target reveals two empty entries:

| trainID | Cityscapes class | cluster count |
|--------:|---|--------------:|
| 0 | road | 16 |
| 1 | sidewalk | 7 |
| 2 | building | 15 |
| 3 | wall | 3 |
| 4 | fence | 3 |
| 5 | pole | 1 |
| **6** | **traffic light** | **0** |
| 7 | traffic sign | 1 |
| 8 | vegetation | 14 |
| 9 | terrain | 2 |
| 10 | sky | 3 |
| 11 | person | 2 |
| 12 | rider | 1 |
| 13 | car | 7 |
| 14 | truck | 1 |
| 15 | bus | 2 |
| 16 | train | 1 |
| **17** | **motorcycle** | **0** |
| 18 | bicycle | 1 |

**No cluster maps to motorcycle (trainID 17).** **No cluster maps to traffic
light (trainID 6).** Pseudo-labels generated by this LUT cannot, as a
matter of arithmetic, contain a single pixel of either class.

This is consistent with the user's recall: "We have actually recovered all
the dead or almost all the dead classes except two in our pseudo levels."
The two are motorcycle and traffic light.

## Why this kills downstream PQ for those classes

Stage-2 trains the Cascade Mask R-CNN on these pseudo-labels. With zero
motorcycle examples, the cascade never learns a motorcycle-discriminative
cluster prediction. Stage-3 EMA self-training reinforces what Stage-2
learned (no motorcycle). Stage-4 fine-object loss adds SAM3-mask
supervision *for* motorcycle on the *unified-thing channel* of the
semantic head — but this never reaches the cascade ROI heads, which
operate on per-cluster classification.

The eval Hungarian re-matches at val time, but it can only match clusters
the cascade actually predicts. With no motorcycle cluster in the cascade
output, no Hungarian assignment lands on motorcycle. PQ_motorcycle = 0.09
on local eval — essentially zero.

## Implication for the dead-class recovery plan

The plan in `docs/plans/2026-05-05_dead_class_cascade_recovery_plan.md`
needs an addendum:

- **Tasks 2-4 (rare pool, yaml, FedLoss/EQLv2)** remain valid for the
  partially-recovered classes that *do* have ≥ 1 cluster: **rider** (PQ
  21.06, 1 cluster), **person** (PQ 15.42, 2 clusters), **pole** (PQ 3.01,
  1 cluster), **bicycle** (PQ 46.43, 1 cluster — already strong).
  Rebalancing helps these.

- **For motorcycle and traffic light**, none of those levers can recover
  the class because the model has no cluster to *be biased toward*. The
  only protocol-compliant fixes are upstream:

  1. **Use SAM3-enriched pseudo-labels.** Your existing
     `scripts/inject_sam3_dead_classes.py` (executed 2026-05-04) maps
     SAM3 motorcycle (idx 2) → CUPS cluster 66 in the enriched
     directories
     (`cups_pseudo_labels_sam3_dead_only`, `_enriched`, `_combined`,
     `_refined`). Retraining Stage-2 → Stage-3 → Stage-4 from these
     enriched labels gives the cascade a motorcycle-shaped cluster to
     learn. Eval Hungarian re-matches at val time, so this is
     **protocol-compliant**.

  2. **Re-fit the k-means with a SAM3-seeded motorcycle centroid.**
     Augment the centroid initialization with the mean DINOv3 feature
     of SAM3 motorcycle masks. Re-run pseudo-label generation.
     Equivalent to (1) but with cleaner cluster structure.

  3. **Add an 81st centroid manually.** Cheapest of the three. Add one
     centroid seeded from SAM3 motorcycle features, set
     `cluster_to_class[80] = 17`, re-run pseudo-label generation. Same
     for traffic light (trainID 6) → `cluster_to_class[81] = 6`.

  Option (1) is the cheapest in engineering effort because the
  infrastructure already exists. Option (3) is a 5-line patch to the
  centroids file plus a re-run of pseudo-label generation.

## Recommended next action

Confirm via a `find ... cups_pseudo_labels_sam3_dead_only/ -name "*_semantic.png"`
spot-check that the enriched directory has cluster 66 pixels in

## What does NOT work

- **Lowering eval thresholds, per-class Hungarian overrides, fixed
  cluster→27 mapping at eval.** All forbidden by the user's
  protocol-parity constraint with the CUPS baseline.
- **Path-B fine-object loss alone.** Operates on the semantic head
  unified-thing channel only; doesn't teach the cascade a new cluster.
- **Rare-pool / RFS / FedLoss / EQLv2 alone.** Can amplify a quiet
  cluster but cannot create one that doesn't exist.
