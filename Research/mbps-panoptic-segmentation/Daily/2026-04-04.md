# 2026-04-04

## Summary

Major evaluation protocol correction. All previous COCO mIoU numbers from `mmgd_cut.py` (including the 46.39% "best result") were computed with **per-image Hungarian matching** — an oracle-like protocol not used in any published paper. Identified and fixed by tracing the CUPS `_matching_core` source code. The correct CUPS-standard protocol gives 27.30% mIoU (baseline) and 27.75% (R6), which are properly comparable to published numbers.

Also completed the COCO panoptic (PQ/SQ/RQ) evaluation infrastructure from scratch, went through 4 broken iterations before arriving at the correct implementation.

### 2. COCO panoptic evaluation — 4 broken iterations

**Iteration 1** (per-image 1-to-1 Hungarian): mIoU=27.57%, PQ=2.74% — K=54 > C=27 leaves 27 segments unmatched (void)

**Iteration 2** (per-image argmax): mIoU=61.71%, PQ=30.07% — oracle upper bound, not a real metric

**Iteration 3** (global Hungarian, K=27): mIoU=19.09% — NCut local IDs not globally consistent; treated as global by mistake; also K=27 too few clusters

**Iteration 4 (CORRECT)**: Global k-means (K=54) → global confusion matrix → Hungarian (27 pairs) + argmax fallback (27 unmatched) → fixed mapping. This matches CUPS `panoptic_quality.py` lines 278–288.

### 3. Evaluation protocol root cause
- `mmgd_cut.py` calls `hungarian_miou(global_pred, gt)` **per image** after applying `seg_to_cluster`
- Per-image Hungarian: each image independently maps its 27 clusters to 27 GT classes → flexible, inflated
- CUPS standard: global cost matrix + one-shot Hungarian + argmax for unmatched → fixed, honest
- Difference: **+19 mIoU points** from per-image vs global (46.39% → 27.30%)
